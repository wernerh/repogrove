# Production hardening checklist

Status legend: PASS / FAIL / PARTIAL / NOT VERIFIED. This checklist is aspirational until
a real deployment exists. One does as of 2026-10-02 (https://www.repogrove.com, ADR-002
addendum), so items below are now verifiable, but most have not yet been re-verified against it.

| Item | Status | Notes |
|---|---|---|
| No secrets committed to Git | PASS | `.gitignore` blocks `.env*`, key files; `scripts/factory/check.py` scans for secret-looking strings |
| No real personal data committed | PASS | No PII collected yet; policy in `SECURITY.md` |
| Dependency vulnerability scanning in CI | PASS | `.github/workflows/ci.yml` runs `npm audit --audit-level=high`; Dependabot configured for `npm` + `github-actions`. Re-ran `npm audit` fresh 2026-09-28: 0 vulnerabilities at any level (2 prior moderate findings resolved by dependabot's vitest 5.0.1 bump, PR #15) |
| Least-privilege `GITHUB_TOKEN` permissions per workflow | PARTIAL | `ingestion.yml` (`contents: write`, needed) and `ci.yml` (`contents: read`, added 2026-09-27 — see SEC-001) declare explicit permissions; `design-screenshots.yml` defaults to `contents: read` with a single job-scoped `contents: write` override (`commit-screenshots`, RG-6, applied by the owner 2026-09-28, reviewed 2026-09-28 security run 7 — unreachable from the workflow's `pull_request` trigger). `factory-guardrails.yml` still relies on the repo/org default because CLAUDE.md rule 7 forbids any lane from editing that file — owner action needed. Re-checked 2026-09-28 (run 7): unchanged |
| Branch protection on `main` requiring CI | FAIL — owner action needed (SEC-005) | Recommended to the owner since the bootstrap PR; factory cannot enable it itself. Confirmed for real 2026-10-01 (security run 10): the same call now returns a clean `404 "Branch not protected"` — GitHub's own answer, not a proxy artifact — so `main` is confirmed to have no protection rule today. See `docs/security/findings/SEC-005-branch-protection-not-enabled.md` |
| Dependabot security alerts enabled (repo setting) | FAIL — owner action needed (SEC-003) | Added 2026-09-28 (security run 4): `GET .../dependabot/alerts` returns "Dependabot alerts are disabled for this repository" — a real GitHub-side answer, not a proxy block. Distinct from the `dependabot.yml`-driven version-update PRs, which are already running (#28/#29/#30). Free, zero-downside, one-click fix (`Settings → Code security → Dependabot alerts`) the factory can't make itself — the enabling API endpoint is blocked by this sandbox's own proxy before it reaches GitHub, so whether the GitHub App also lacks admin scope for it was never directly tested. See `docs/security/findings/SEC-003-dependabot-alerts-disabled.md` |

A live target now exists (Azure Static Web Apps, 2026-10-02), which supports headers via `staticwebapp.config.json`; none exists in the repo yet (TECH-DEBT.md). Confirmed 2026-10-01 (security run 10): still no `src/app/**/api` directory or `middleware.ts` anywhere in the tree. Revisit once either gains a real server endpoint |
